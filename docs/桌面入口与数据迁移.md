# 桌面入口与数据迁移

在程序文件夹运行 `安装桌面入口.ps1`，会为当前用户创建桌面和开始菜单的 MotionControl 图标。开始菜单搜索 MotionControl 后，右键可选择“固定到任务栏”。这些入口指向同一个独立程序，不指向某一份 Python、临时开发目录或浏览器。

入口位于 Windows 返回的用户漫游应用数据目录中的 `MotionControl\Launcher\MotionControl.exe`。它记住正式程序文件夹，通过同一个 `START.ps1` 启动或复用服务。连续双击共用启动锁；复用前核对服务身份、程序文件夹、实际数据目录与配置状态。其它目录的程序占用管理端口时，给出说明，不关闭它或另起一份争用端口。

复用还需核对后台加载的代码内容标识和完整游戏配置版本。程序文件更新后，即使发行版本号相同，也不能把旧后台当成新版本。发现同目录旧后台与原配置不一致、且游戏输出已暂停时，入口等待它正常退出后重新载入；控制仍在运行时先提示暂停。C 盘联接路径和迁移后的实际路径会按相同目录核对。

## 配置如何定位

所有游戏、动作、语音、校准和摄像头缓存从 `motioncontrol.user_paths` 取目录。前后倾模型的本机登记也跟随这个目录。管理员重启通过命令参数显式传递同一目录，在导入任何配置模块之前生效。

正常启动先读取当前用户注册表中的 `Software\MotionControl\DataLocation`，再核对目录内 `.motioncontrol-data.json` 的身份。位置记录作为一个完整文档写入。Windows 的正式本地应用数据目录优先于旧终端继承的环境变量；目录重定向和联接按实际位置解析。数据随 Windows 文件夹迁移后，只接受身份相符的目录，成功定位后更新位置记录，不按文件修改时间猜哪一套属于用户。

旧版程序内的配置首次迁移采用临时文件完成写入后再替换，原文件不删除，已有目标文件不覆盖。迁移写入失败时停止并保留原数据，下次可以重试，不留下半写入文件或继续用默认配置运行。

如果手动把整份目录搬到系统没有记录的新位置，入口会请用户选择一次迁移后的原文件夹，再持久记住。所选文件夹必须有原配置或身份记录。找不到已登记的数据时停止启动，不创建一套默认配置掩盖问题；取消定位不会修改原数据。迁移时应保留整个数据目录，包括开头带点的身份记录、最近有效副本、动作与校准文件。

`MOTIONCONTROL_USER_DIR` 仍是显式目录覆盖，供隔离测试或明确指定其它数据使用。开发及测试不得把临时目录登记成用户正式位置。任意位置的手动搬移没有路径线索时需要一次选择；不承诺扫描所有磁盘或凭名称猜测数据。

程序文件夹也可以迁移。原入口发现启动文件不存在时，会让用户选择新目录里的 `START.ps1`，不需要重建已固定的任务栏入口。快捷方式自身被用户删除时可重新运行安装脚本。

## 完整退出

顶栏帮助菜单提供“退出程序”。关闭网页仍保留后台；完整退出先保存页面已有草稿，录制中或保存失败时保留页面并说明处理方式。后台接到退出请求后先释放按键，取消迟到的启动和命令，再分别关闭麦克风、相机、录制、运动记录和端口。一个模块收尾失败会留下具体记录并继续处理其余模块。

页面收到退出确认后停止正常请求及预览，核对管理服务是否已经关闭。超时或无效响应保留“退出尚未确认”，可以重新核对；如果另一个实例已经启动，提供“连接新程序”。正在退出的实例不会被桌面入口当成可用程序复用。

## 保存与恢复

完整游戏配置内包含自建游戏身份，独立自建游戏文件保留作兼容副本。保存选择、绑定、自建游戏和最近有效副本使用同一个可恢复文件事务；写入失败恢复旧文件和旧内存。损坏主配置从最近有效副本恢复，损坏内容另外保留，相同损坏内容不会因反复重试无限生成副本。没有有效副本的损坏文件保留并明确报错。

运行中发现文件变化后协调重读，身体与语音使用同一份绑定；重新绑定时先释放游戏输出。页面自动跟随已提交配置。有未保存改动时保留草稿并停止自动覆盖，用户选择“合并我的修改再保存”后，仅将编辑过的行合到最新配置。短暂连接故障只自动重试读取一次，保存、添加、删除不自动重复提交。

通用设置也有最近有效副本。临时写入失败后，当前设置继续生效，后台保留最新快照并最多尝试四次，页面明确显示尚未保存；可以点“重新保存”。保存完成后，原页面草稿凭同一后台的回执自动完成，不重复执行设置操作。后台已经重启时保留原草稿供手动重试。文件及有效副本均无法读取时保留原件，页面使用临时设置，选择“保存当前设置”后才归档原件并保存；正常退出会先提示处理尚未保存的设置。

启动记录在数据目录 `logs` 中；桌面入口自身的最后一次启动记录位于入口旁的 `last-start.log`。这些是本机诊断资料，不提交到仓库。

## 检查边界

故障检查使用隔离目录，覆盖文件缺失、无效内容、锁定写入、部分提交回退、过期窗口、外部更新、真实文件夹搬移、中文空格路径、管理员交接、原生入口编译和快捷方式目标。浏览器检查使用实际页面模块与隔离接口。这些结果不表示已完成所有摄像头、真实游戏、任意第三方搬盘工具及长时间运行的兼容验证。

## 2026-10-26：修复隔离目录中的桌面入口

实查发现用户打开的旧入口位于商店应用的独立缓存目录，与普通桌面入口的注册位置不同。新版默认装到用户主目录的 `Apps\MotionControl`，避开商店应用对应用数据目录的重定向。程序位置和原设置目录写入入口旁的完整记录，并随原生程序内嵌；本地记录缺失或损坏时回退到安装时基线，不要求用户找启动脚本。真正迁移程序后选择程序文件夹，原生入口记住新位置；原设置通过目录身份核对并显式传递给后台。

启动优先使用正式安装的 PowerShell 7；没有时使用 Windows 自带环境，不再依赖开发工具缓存中的运行程序。原批处理入口同时保留该回退。启动脚本兼容旧环境的中文编码、网页读取和目录联接，桌面及开始菜单均使用包含原生图标资源的可执行文件。安装器提供 `-UserDataRoot`，维护时可直接指定已经核对过的原设置目录。

检查包括真实编译、快捷方式目标与图标资源、位置记录删除/损坏后的内嵌回退，以及 Windows 自带环境下中文路径与目录迁移。`--diagnose <报告文件>` 只读核对位置，不启动后台；`--no-browser` 可用实际入口验证服务启动而不反复打开页面。

实际启动补测发现 Windows 自带环境会将手机通道程序的错误流提示提升为异常；该通道只是可选便利功能，现已隔离失败，不能阻止电脑后台继续启动。29项桌面与启动检查通过，包括该提示的原生错误流复现。旧桌面、开始菜单及隔离缓存中的已知入口一并更新到相同程序和图标，新的正式入口保留原设置目录身份。
