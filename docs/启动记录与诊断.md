# 启动记录与诊断摘要

实验与诊断的“导出摘要”提供一个本地文件，包含版本、加载代码标识、程序与数据位置、配置保存状态、摄像头状态及已有性能数值。不读取或打包配置正文、日志正文、语音文本、账户、配对密钥、原始骨骼、画面或录制文件。模型只输出是否可用、缺件数量和运行数值；未知占用或延迟保留未知，不用零冒充测量。下载与完整配置备份复用相同的文件导出入口。

桌面启动的程序输出分别写入用户数据目录 `logs/startup.stdout.log` 和 `startup.stderr.log`，每份不超过一兆，各保留四个历史文件；运行很久也轮换。原生库直接写系统句柄的早期输出保留在 `bootstrap.stdout.log` 与 `bootstrap.stderr.log`，下次启动前按同一上限归档；当前原生输出由系统接收，运行期间没有承诺硬性限额。原生桌面入口的启动回执保留当前及三个历史文件，每份最多约192千字节。日志保存失败不能改变后台实际启动结果，诊断摘要会标记当前输出记录是否失败。

处理器与内存使用同一份每秒最多一次的按需采样，页面和后台记录共用结果，不增加采样线程。处理器数值表示后台自身所有线程占整机的比例；内存为该后台工作集。不包含 Kinect 原厂服务、独立前后倾进程、浏览器或游戏。不能将整张显卡占用直接归到单目模型。单目模块继续沿用处理器运行与自身显存字段。

维护时先区分四种状态：空闲、只识别、开启游戏控制、录制。每种都记录供帧率、识别率、各处理环节、预览、处理器、内存与适用的显卡进程；使用相同画面和时长比较。页面隐藏停止预览请求，后台预览需求到期后停止编码；可选模型无消费者时停止进程。诊断导出只在点击时构建，不新增状态轮询，不进行模型加载或画面采集。

本轮核对了真实运行中的 Kinect 识别与对照进程状态、预览和各处理环节；页面隐藏、停止、排队和输出生命周期已有针对性检查。用正式解释器、原配置的隔离副本完成两次真实后台启动、摘要下载、正常退出和历史保留，和平精英身份及原绑定完整，原用户文件未改变。没有为了测量开启用户游戏按键或新录像；不同真人动作、实际游戏负载及长时间运行仍需分开验收，私人测量和原始资料不提交。
