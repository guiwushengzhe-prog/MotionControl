# 后台进程和摄像头退出

## 2026-10-08

### 问题和范围

- Kinect 二代使用 `KinectCamera.exe`，通过本机管道供帧，不是另开网络端口录制。
- 普通 USB 摄像头通过主后台内的采集线程读取，没有独立的 Python 采集进程。
- 强制结束后台会跳过 Python 清理，原先独立采集进程可能继续占用设备。
- 只管理本次后台启动的内部子进程及其后代，不按名称结束其他实例，也不追溯接管旧进程。

### 实现

- `owned_process.ensure_lifetime_job()` 在创建子进程之前，先将当前后台加入 Windows 作业对象（操作系统管理的一组进程）。以后创建的内部子进程自动继承归属，覆盖 Kinect、可选语音识别、设备枚举、编译及配置助手。
- 设置“最后一个作业句柄关闭时结束成员”。句柄不可继承，只有后台持有；正常退出、崩溃、关闭窗口和外部强制结束都由 Windows 回收。
- 不在退出清理中主动关闭作业句柄，因为后台自身也属于该作业，提前关闭会打断保存和设备释放。
- 提权配置助手由 Windows 启动，主动加入原后台的命名作业，再立即关闭自己的句柄；如果原后台已经退出，则取消执行。
- 普通摄像头和 Kinect 在采集线程结束时就释放设备；仍等待其他识别线程结束才允许新一轮识别，避免旧识别结果污染新会话。
- Kinect 重复释放不会再次操作已关闭管道；结束子进程后等待其真正退出。后台正常关闭也等待相机停止，并保证控制内核完成清理。

### 验证边界

- 使用真实 Windows 轻量子进程验证退出行为，不启动实体摄像头，不产生照片、视频或真实游戏输出。
- 官方机制依据：[微软作业对象说明](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。
- 具体验证结果在完成后追加。

### 完成后的验证结果

- 相关回归：`100 passed in 9.15s`；差异空白检查通过。
- 真实 Windows 子进程验证：正常退出、强制结束、异常退出均回收子进程和再派生进程；另一个同名解释器实例继续运行。
- 输出管道堵塞时仍能回收；Kinect 读取线程启动失败后，已经启动的测试采集进程被结束并等待退出；重复释放不再访问已关闭管道。
- 从独立父进程启动 PowerShell 助手，执行实际归属绑定代码：后台退出后助手退出；后台已退出时助手在绑定步骤取消。没有执行防火墙检查或写入，也没有请求真实管理员提权。
- 可选语音助手并发启动只创建一个进程；正常关闭和不响应关闭请求两种情况下均退出，管道、读取线程和日志句柄均关闭。
- 替代 USB 设备验证：识别尚未结束时，采集停止就释放设备；待旧识别结束才允许下一轮启动。关闭相机失败时仍清理控制内核。
- 没有启动电脑端服务，没有调用实体摄像头，没有进行真人或真实管理员重启验收；这些不计入上述检查结果。
