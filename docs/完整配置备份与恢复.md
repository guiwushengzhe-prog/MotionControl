# 完整配置备份与恢复

设置 → 实验与诊断 → 配置备份与恢复。备份只在本机生成并由浏览器保存，不上传云端。

## 包含的数据

完整游戏配置，包括自建游戏身份、每个游戏的绑定、模式、区域和启动权限；身体动作映射、通用与个人语音、宏、自定义动作及下载动作；运动记录、录制偏好；通用设置、头部与身体校准、双摄像头校准；前后倾个人学习、模型本机登记及动作学习的骨骼记录。

账户凭证、手机配对钥匙、设备发现身份、相机探测缓存、防火墙记录、模型权重和普通音视频不进入配置包。参考场景照片和录制设置中的自定义头像可能在包内，界面明确说明，备份应由用户妥善保管。恢复不覆盖当前用户目录的身份标记。

普通导出会检查已登记的配置格式、动作签名及学习索引的完整性。游戏身份、宏、动作与语音复用加载时的校验规则；不会为了导出而把损坏内容改成默认值。尚未保存的通用设置或个人学习会阻止“成功导出”的假反馈。

## 恢复方式

- 本机恢复：恢复包中的完整配置、校准与模型登记；包含的文件整体替换，缺少的旧配置清除，避免新旧状态混杂。
- 跨电脑恢复：恢复游戏、动作、宏、口令、运动与录制偏好，合并明确允许的通用偏好及头部调节参数；目标电脑的相机和声音设备、身体站姿、头部校准、双摄像头校准及本机模型登记保留。录制头像和屏幕裁切清空，运动同步进度重新建立。

预览显示游戏、自建游戏、宏、动作与文件数量；文件清单默认收起。相同目录身份默认选择本机恢复，其余情况默认跨电脑恢复，执行前仍可调整。

恢复前必须暂停游戏控制并结束录制。保存操作先处理页面草稿，随后将当前原文保存在用户目录的 `backups/恢复前-日期-编号.zip`。该副本还保留当前有效副本；即使原文损坏也不丢弃，损坏内容仍需明确修复后才能作为正常配置载入。

## 启动与失败处理

1. 检查配置包大小、清单、摘要、内容格式与学习文件引用，拒绝目录越界、未知文件、重复项及不完整包。压缩包最多32兆，解压后的总量最多128兆，文件最多1024个，不直接解压外来路径。
2. 写入待恢复包及标记，两者使用统一的可恢复事务；生成恢复前副本失败则不准备恢复。
3. 请求当前后台正常退出，页面沿用完整退出的确认流程，不在仍运行的配置对象上替换文件。
4. 用户再次打开程序时，在配置对象创建之前恢复。主文件、有效副本、旧中断保存记录和待恢复标记参与同一事务；写入失败整体回退，保留待办供下次继续。
5. 启动检查读取待恢复的游戏状态，避免把恢复前选择误认为启动后必须保留的状态；遇到恢复中断，从事务中投影原定目标，不提前修改原配置。

准备恢复的接口只允许本机同源页面操作，读取不自动重复写入。备份功能没有新增后台轮询；只有用户操作时才检查与打包。

## 维护入口

- 文件范围、打包、预览、跨机处理和事务恢复：`motioncontrol/configuration_backup.py`。
- 游戏完整文档及共用格式校验：`GameProfileStore.configuration_document`、`validate_selection`。
- 启动目标核对：`motioncontrol/startup_identity.py`；实际应用位于 `server.py` 配置对象创建前。
- 页面：`web/js/configuration-backup.js`，沿用 `core.js` 的配置队列与 `lifecycle.js` 的完整退出。
- 针对数据与浏览器行为的检查：`tests/test_configuration_backup.py`、`tests/test_configuration_backup_web.py`。

新增持久配置时同时评估用户目录登记、备份范围、跨电脑恢复含义和加载校验；不能只加文件名而遗漏恢复语义。私人验收副本与运行结果继续放在忽略目录，不提交。
