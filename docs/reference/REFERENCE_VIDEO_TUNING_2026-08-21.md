# MotionControl v0.9.3 参考视频调参记录

参考输入：用户提供的 12.433 秒、720×1280、30 FPS 站立正视视频。该视频用于验证“自然站立并非数学静止”这一事实，并调整校准时序/样本策略。

## 实测摘要

- 视频帧数：373。
- 视觉上可作为自然正视基线的最长稳定段约为 `1.50 s ~ 9.13 s`，约 `7.63 s`。
- 稳定段脸部局部逐帧仿射旋转 MAD 约 `0.026°`，95% 绝对偏差约 `0.080°`。
- 稳定段逐帧水平/垂直局部位移 95% 绝对偏差约 `0.60 px / 0.32 px`。
- 稳定段逐帧尺度变化 95% 绝对偏差约 `0.094%`。
- 同一使用链路页面曾显示手机姿态约 `16.74 FPS`；因此固定“采几秒”不如“时间 + 有效样本数”更可靠。

## 写入 v0.9.3 的默认校准值

- 语音后准备：`1.0 s`。
- 最短自然采样：`2.2 s`。
- 正常完成目标：`32` 个有效样本。
- 最大墙钟时间：`6.0 s`。
- 到墙钟时最低仍可成功：`20` 个有效样本。

在约 16.74 FPS 的手机姿态输入下，32 个样本理论上约需 1.91 秒，因此 `2.2 s` 成为正常最短采样；即使短时掉帧也仍有余量。低 FPS 时程序会继续等待样本，而不是因为固定秒数到了就草率结束。

## 没有从视频硬算的参数

没有把这段视频的像素位移直接换算成 PnP yaw/pitch，也没有据此硬改灵敏度、18°/12° 信号跨度或基础死区。原因是这段视频没有保存 MediaPipe Pose/PnP 的实际角度输出，也没有明确的“左转多少度/抬头多少度”标注。把像素抖动冒充角度会得到伪精度。

基础稳定区仍为 `0.10`；真正运行时会由每次语音校准测得的 PnP 本底噪声自动放大 `effective_deadzone_x/y`。中心角度也绝不使用参考视频硬编码，每次运行仍以玩家正式位置、自然看屏幕时重新采集。
