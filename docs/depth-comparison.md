# 单目深度对比与运行状态

## 在哪里使用

在「设置 → 实验与诊断 → 单目深度对比」开启实验，选择一个模型。复用电脑摄像头已经送入识别的同一帧，不再打开第二个摄像头；不改变身体走位来源、游戏映射或控制开关。没有启动电脑识别时显示等待画面，实验不会替用户启动设备。

| 候选 | 输出 | 本次用途 |
| --- | --- | --- |
| Depth Anything V2-S 室内米制版 | 米制距离 | 单帧室内距离基线 |
| Video Depth Anything-S 米制流式版 | 米制距离，保留视频历史 | 对比连续运动时的稳定性 |
| ZipDepth 基础版 | 相对逆深度，数值越大越近 | 低开销候选；需另做尺度校准才能比较厘米误差 |

一次运行一个候选，切换后保留各候选上次统计，表格明确标注「当前 / 上次」。停止识别或摄像头失败时结束独立计算进程，释放它的显存。对照实验默认关闭；若前后倾来源选择了下述「单目深度」，则复用同一个计算进程继续识别，不另加载第二份模型。两项均未使用时不复制画面、不创建额外计算线程，也不加载这些模型库。

### 怎样看结果

- 输入短边可选 280、392、518；各模型会按自身步长对齐尺寸，表格显示实际输入宽高。相同短边不保证相同像素数。
- 帧率上限可选 2、5、10、15、30。表格显示实际完成帧率，包含限速和排队影响，并非模型理论上限。只保留最新一帧待处理，赶不上时跳过旧帧。
- 前两帧作为预热，不计入平均模型耗时、耗时分位数和实际帧率。统计窗口最多 120 次完成，切换或重新开启后重新统计；加载时间与模型单帧耗时分开。
- 显存显示所选模型进程实际保留的显存，包含其计算库缓存，不代表全机显存或单纯权重体积。运行时与既有识别共用显卡，实际负载也会互相影响。
- 原始平均误差、固定校准后平均/95%误差分列，最多统计最近 3000 个有效点；正负偏差另由接口提供。校准帧不进入验证统计，没有可靠参考时不编造误差。
- 静止抖动仅使用参考距离及画面位置连续稳定的点，至少连续四次稳定后统计相邻帧距离误差变化的均方根，最多 1500 次。该值不是整段视频或游戏手感评分。
- 深度预览每帧按分位数调整颜色范围，以便看清结构。因此同一颜色不能跨帧、跨模型直接当作同一米数；以数值表和参考点明细为准。

### Kinect 参考与尺度校准

只使用同一人物匹配成功、可靠跟踪、与彩色帧相差不超过 80 毫秒的原始深度表面采样。采样位置在关节投影附近，取有效 3×3 邻域中值，排除人体与背景混在一起的深度边缘，再用原厂坐标映射对齐彩色图。原厂骨骼的关节中心通常位于人体内部，不能代替衣服、皮肤表面的实测距离。

「用Kinect固定校准尺度」默认选中；开启实验且取得可靠参考后先采集三秒，再固定下来比较后续画面。两个米制模型只求一个正的乘法系数，不加距离偏移、不用未来参考逐帧重新缩放。模型原始米数、原始误差始终另外保留。关闭自动校准后可查看未经校正的结果，也可点击「重新校准尺度（3秒）」。

ZipDepth 以相对逆深度拟合固定米制换算，需要足够参考和前后距离差异。拟合必须保持近大远小、相关系数至少0.5，并通过残差检查；否则“几乎不变的距离”可能有很小平均误差，却没有跟随深浅变化。失败保留此前有效尺度并显示原因；没有有效尺度时仍展示原始相对值。固定尺度后才以未来帧计算误差，超出可靠拟合范围的值不硬换算成米。所有尺度只在当前实验进程和相同来源中使用，重新开启时重新校准，不修改神经网络权重。

面板直接报告当前同人同步的 Kinect 躯干表面中位距离、范围和可靠点数，无需开启单目模型或手工输入距离。只采用躯干参考，手伸到镜头前不改变躯干统计。原厂关节中心距离另在运行状态显示；人物数据超过250毫秒或表面和彩色图不同步时停止报告当前距离，不沿用旧值。模型表格仍保留各候选最近一次结果，两者的统计时段不同。

ZipDepth 尚未校准时，误差栏显示「待尺度校准」，点明细显示原始相对值；表格分别列累计验证点数和本帧原厂参考点数。校准后仍超出可靠尺度范围的点明确显示未换算。米制模型附带有方向的平均偏差：例如「偏远92.5厘米」说明预测整体偏远，不能将这个值解释为前后倾角度误差，或通过逐帧对齐把它消掉。

### 人体裁切与输入大小

「输入范围」可选全画面或人体附近。人体位置直接复用当前 MediaPipe 骨骼，不重复执行人体检测；现用接口不公开内部裁图，因此按已有位置从同一原帧提取一次区域。输入短边固定后保留长宽比例，实际尺寸显示在表格中。正方形附近的人体窗口通常能减少长边像素，但不保证每种取景都省计算。

首次可靠人体点确定带20%余量的固定像素窗口，要求双肩和双髋可靠入镜，排除只有头部或极小误检的窗口。后续动作不逐帧变焦；参考点同步换算到窗口坐标，窗口外参考排除。移动到窗口外时点「重新取人体范围」。临时丢失原厂骨骼不反复丢弃窗口和尺度，真正换人或相机/方向/尺寸变化后重新初始化。未找到足够可靠人体点时等待，不暗中用全画面代替。

只输入人体仍可估计身体各部位的前后关系，但裁切改变画面上下文和视野，绝对米数不能保证保持原尺度，所以每种范围分别校准。前后倾应比较躯干上下部位的相对距离和站姿基准，不能只看整个人离镜头远近。距离对照与下面的单目前后倾控制分别选择；开启距离对照本身不会改变控制来源。

相机、模型、所匹配人物或画面几何变化后重新初始化视频历史及尺度。参考缺失时仍可查看模型画面、耗时和显存。Kinect 是本机对照测量来源，也会受遮挡、边缘和跟踪误差影响，不能将某一次误差称为所有场景的真实精度。

### 前后倾方向的独立核验

继续使用第二段完整20秒，补齐末尾49张图的原有身体模型定位，不新录制。195张彩色图均找到可靠原厂肩髋参考。以最初3秒的中位姿态为基准，第6秒后136帧做方向统计；原厂肩髋角度变化覆盖约前倾14.2°、后倾8.0°。其中超过3°的前倾115帧、后倾9帧，超过7°共23帧，后倾样本较少。

初次按图像骨骼点采样，195帧中107帧的一个肩点对应原始深度比真实肩部远超过25厘米，多数落到约一米外的背景；这些背景点不能当作可靠人体表面。另用 `KinectRecordedTorso.cs` 从原始深度重建真实肩髋表面坐标，工厂映射与录制设备身份核对；前146帧与应用记录的同名表面距离平均差约0.0012厘米，原厂表面肩髋深度差与骨骼角度相关约0.964。

以下是在原厂已确认采样位置上检验模型深度的方向信号，**并非完整单目识别准确率**。每个来源先扣除相同3秒基准，比较肩部相对髋部的深浅变化；ZipDepth按逆深度的物理方向取负号，不换算米数，不搜索延迟、不调换标签。全画面/人体范围各运行三个真实模型195帧。

| 人体范围候选 | 超过3°时方向同向帧数 | 超过7°时方向同向帧数 |
| --- | --- | --- |
| V2-S | 43 / 124 | 20 / 23 |
| VDA-S | 76 / 124 | 23 / 23 |
| ZipDepth | 85 / 124 | 22 / 23 |

本段较大动作有可用深度信号，小幅前倾及回正仍不可靠；全局米制距离校正不能补出缺失的相对深浅变化。后续应验证躯干内部区域的深度读出，并用原厂骨骼作为前倾/回正/后倾监督与独立验收依据。米制误差不再作为这个动作的唯一筛选依据，ZipDepth也不能仅因没有米数就被淘汰。最终动作识别必须仅依赖普通摄像头；本次原厂辅助确定采样点的诊断不等同于达成该目标。

复现工具为 `evaluate_lean_recording.py`（准备/真实模型计算/方向统计）、`KinectRecordedTorso.cs`（从保存深度重建原厂表面位置）及 `plot_lean_recording.py`（动作曲线）。原始图、逐帧数据和图表仍保存在个人录制的analysis目录，不提交仓库。本项仅分析，没有改变正式前后倾控制或重新开启设备。

## 单目前后倾（实验）

在「设置 → 实验与诊断 → 灵敏度实验」将「前后倾来源」选择为「单目深度（实验）」，再按需要开启「身体前倾前进 / 身体后倾后退」。侧倾及首步仍按各自原有来源运行，选择单目不会开启游戏控制或摄像头。

单目默认使用VDA-S；可在「单目前后倾模型」切换另外两个候选。该选项与此前距离对照的模型偏好分别保存，但同时只运行当前所需的一份模型。单目前后倾固定使用人体附近窗口，复用现有MediaPipe定位；帧率上限最低10帧/秒，达不到时按实际完成帧率运行。深度输入短边仍沿用上方选择。

### 预测与动作

- 只读取彩色画面、已有二维骨骼和单目模型深度。不把Kinect肩髋、真实距离或原厂角度送入预测；没有原厂参考也能初始化并输出。
- 双肩双髋内缩后的胸腹区域取六层、每层五块邻域中值，共30块；排除肩部轮廓上容易落到背景的单点。各层除以当帧躯干中位深度，读取上下相对深浅及身材比例；ZipDepth先将逆深度恢复为相对深度方向，不声称得到米数。
- 开始或「重设站姿」后自然站直3秒，以最后约1.1秒的中值建立基准。默认几何读出是相对倾斜估计，非经过相机内参标定的绝对角度；尚未通过独立真人动作验收，界面明确标为实验几何估计。
- 复用原有短时平滑及7°触发、5°释放门限。前倾保持时持续前进，后倾保持时持续后退，回到稳定区释放；前后方向互斥，不增加动作顺序、累计位移或复杂回正规则。
- 输入无效、结果超过250毫秒、停识别、模型退出或切换来源时释放原有方向。重新量站姿后，旧版本尚在计算的结果不能恢复动作。
- 面板显示三秒倒计时、前倾/中立/后倾、估计角度、连续倾斜强度、采样区域数和学习状态。骨骼/触发录制保留单目结果及其年龄，离线回放按记录年龄换算时钟，不打开模型或进行个人学习。

### 自然动作学习

「用Kinect教单目前后倾」默认关闭。开启后，Kinect仅给同时刻的可靠角度标签；需要同人物可靠肩髋、同步不超过80毫秒。自然前倾、回正、后倾时每秒最多积累四组低维特征，不新增视频录制、不修改深度神经网络权重。一直站直只能增加中立样本，不能教会未做过的两个方向。

至少64组、覆盖三个状态后冻结一个小型线性读出，隔开一秒再收集后续动作作验证。至少32组后续样本也须覆盖三个状态；以真实使用的中立读出为原点，要求平均差不超过3°、95%差不超过6°、明确倾斜的方向同向率至少90%、中立误触比例不超过5%。不通过就继续用当前读出，收集新样本后再试；有旧个人读出时，只有新方案在同一后续样本上更好才替换。

学习文件 `monocular_lean_learning.json` 保存在个人数据目录，不提交仓库。相机、模型权重、取景窗口、输入大小或特征版本变化后使用独立档案；重设站姿会撤销尚未验证的候选并重新量中立。已通过验证的个人读出后续可在没有Kinect时使用。验证仅证明同一来源的后续动作，不能代替换人、换衣服或换站位的泛化验收。

### 第二段实录的完整单目回放

`replay_monocular_lean.py` 将195张原彩色帧和已有二维定位走过正式独立计算进程、胸腹读出、中立校准及动作控制器。原厂数据不送入上述链路，只在输出评分时使用。最初3秒量基准，第6秒后136帧评分，不搜索时间偏移、不用本段未来标签修正预测。固定使用7°触发/5°释放，对照也按同样门限计算。

| 胸腹读出候选 | 相对角度平均差 | 三状态同向帧数 | 平均模型计算 | 进程预留显存 |
| --- | --- | --- | --- | --- |
| VDA-S | 2.74° | 97 / 136 | 32.7毫秒 | 584MB |
| V2-S | 6.50° | 88 / 136 | 21.7毫秒 | 264MB |
| ZipDepth | 11.13° | 30 / 136 | 8.4毫秒 | 96MB |

VDA较适合作为本轮起点，但不是可靠识别已经完成：参考前倾29帧中26帧识别为前倾，后倾5帧中4帧为后倾；参考中立102帧中34帧仍被判前倾、1帧判后倾，多在门限附近。整段中立范围内另有明显偏差，不靠加复杂动作规则掩盖。后倾样本很少，三个候选也没有用这段数据训练出经独立留验的个人读出；个人学习须继续用自然动作积累并通过后续验证。

这些数值来自第二段实录、单一站位及当前胸腹读取方式，不等同于模型总体排名或现场游戏表现。报告及逐帧输出留在该录制的个人 `analysis` 目录。`extract_lean_regions.py` 可缓存VDA深度与胸腹特征供重复诊断，`replay_monocular_lean.py --cached` 只读缓存；完整回放则运行所选真实模型。原始录制及个人学习文件仍不入库。

## 资源准备

额外资源不加入主程序依赖。使用独立目录与 Python 环境，避免更改现有相机、手部或头姿环境。以下路径仅为示例，可替换磁盘位置；需要兼容 NVIDIA 显卡和驱动。

```powershell
$depthRoot = 'I:\MotionControl-Pose-Models'
python -m venv "$depthRoot\runtime\depth-compare-v1"
& "$depthRoot\runtime\depth-compare-v1\Scripts\python.exe" -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
& "$depthRoot\runtime\depth-compare-v1\Scripts\python.exe" -m pip install numpy opencv-python-headless matplotlib einops easydict tqdm Pillow
python tools\prepare_depth_comparison.py --root "$depthRoot\models\monocular-depth" --python "$depthRoot\runtime\depth-compare-v1\Scripts\python.exe" --activate
```

准备工具使用固定的源码提交和权重校验值，不覆盖已存在且版本不符的源码。下载慢时可显式指定 `--hf-mirror https://hf-mirror.com`，仍校验相同权重摘要。工具在资源目录生成清单，只有加 `--activate` 才原子写入当前用户目录的 `depth_comparison_runtime.json`。注册资源本身不会开启实验。界面「已准备」表示资源文件齐全；模型是否成功加载、是否使用显卡由实际运行状态给出。

源码与权重来自各项目官方仓库或其所列权重：

- [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)：提交 `a561b849ebae10a6f5ef49e26c83cbbcd36c71bf`，室内 Hypersim Small 米制权重。
- [Video Depth Anything](https://github.com/DepthAnything/Video-Depth-Anything)：提交 `4f5ae23172ba60fd7bc11ef671cca678842c7072`，Metric Small 权重，调用官方逐帧流式接口。
- [ZipDepth](https://github.com/fabiotosi92/ZipDepth)：提交 `91f3fd21e131641f51e8d35736d1958350180e3a`，随仓库提供的 `zipdepth_base.pth`。

这些源码、权重和各自许可保存在用户选择的资源目录，不打包到 MotionControl 仓库。分发或商用时依原项目对应源码、具体权重许可处理；不能把另一规格模型的许可直接套用。

## 运行状态增加的内容

复用现有状态刷新，不再另建轮询：

1. 采集与预览：实际尺寸、格式、请求与实际帧率、帧计数、跳帧、骨骼年龄、处理与预览编码的平均及95%耗时、预览大小和年龄。
2. 头部与视角：当前方法、校准、控制是否放行及原因、左右/侧倾/俯仰角、设定与实际死区、防晃倍率、输出量、头姿模型及耗时、上下视角门。
3. 手部与握拳：原厂或模型识别、同帧调度、计算耗时、并行比例、裁切重试、每个方向的控制手、握拳接管、展开与弯曲读数、实际输出量。
4. 动作、区域与学习：入镜状态、持续动作、首步来源、已映射区域与点亮数、两路骨骼角度、分别选定的侧倾/前后倾来源、学习和验证数量。
5. 输出与录制：输出暂停/开启、鼠标或摇杆、虚拟手柄、按住的键和按钮、合流、宏、触发录制状态与最近触发。系统输出量不冒充游戏中的视角角度。
6. 语音：中文说明识别模式及未执行原因，显示采音设备、连接、音量、接收量、音频队列、丢帧/重置、实时与最终结果、命令数量和冲突词条。

仅显示已有状态。深度预览与中间画面在内存中流转，不自动开始视频、骨骼或触发录制。计算错误写入用户目录 `logs/depth-comparison-worker.log`，不因可选模型失败中断相机主识别。
