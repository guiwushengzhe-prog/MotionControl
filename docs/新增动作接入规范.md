# 新增动作接入规范

## 一条接入路径

1. 在动作目录登记稳定编号、中文名称与说明。内置动作、下载动作和自录姿势都从统一目录进入绑定界面，不另建首页动作列表。
2. 识别器只提供动作是否成立、角度或相似度，不直接发送按键。识别参数与当前游戏绑定独立。
3. 当前游戏或模式中的明确绑定决定能否输出。没有绑定、明确选择“不绑”、空动作、失效宏都按未绑定处理。新动作默认不绑，不根据踏步或其他动作推测按键；游戏自带的默认绑定必须在游戏档案里明确可见。
4. 内核用 `_trigger_mapped_locked` 统一判断输出、有效绑定、区域冲突和手机反馈。`_bound_action_triggers_locked` 从统一动作目录筛选，新增动作不再单独补白名单。
5. 页面读取内核的 `effective_bindings`，通过 `triggerMapped` 决定是否显示。首页区域、大字提示、动作标签、最近触发、映射表触发反馈和悬浮窗都遵守同一条件；解绑后旧事件也不能继续高亮。动作库可保留“没绑键”的可选卡片，供用户选择绑定。
6. 原始识别状态可以保留在诊断和录制数据中。它不代表按键已输出，不能直接当作首页或手机上的触发反馈。

## 修改后的必要核对

- 新动作未绑定、已绑定、解绑、切游戏或切模式时，显示与实际输出一致；现有动作和未来任意编号都遵守同一规则。
- 未绑定动作不产生输出或首页触发反馈；已绑定动作持续保持、回正/动作结束释放、断帧释放。
- 绑定有效时才参与区域冲突；删除宏后不能继续显示或触发失效宏。
- 统一校准入口同时重设身体各路站姿和单目前后倾基准，清理旧倾斜输出，并通过版本编号拒收旧异步结果。体感页的重设站姿继续复用这一归零入口。
- 用隔离配置检查上述变化，不修改用户游戏按键、识别来源或学习开关来凑通过结果。

## 单目前后倾的个人学习

- 学习倾角只使用髋、腹、胸的旋转量；头部、手臂、手腕和绝对位置不得直接获得倾角换算权重。学习范围由模型适配器按名称明确提供，不能因增加输出量就自动全部用于拟合。
- 冻结候选后用后续样本验证。前倾和后倾分别核对角度幅度、识别比例和误差，同时核对中立误触；不能只靠总体平均误差或正负方向判断通过。候选还需优于基础估计或当前个人读出。
- 加载历史读出和重新记录中立站姿时复核适用性，不合格的旧权重不得继续生效；原始样本和录制文件保留。可靠深度只用于可选学习与复核，普通单目推断独立运行。
- 基础倾角换算同样限制为髋、腹、胸旋转量；不能只限制后续学习而继续加载包含手臂、头部或绝对位置的基础权重。局部换算使用逐帧角度的中位数归零，不能用中位特征代替非线性换算后的中立角度。
