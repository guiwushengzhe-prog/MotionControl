# 成熟软件设计审查

2026-10-25。按用户提出的稳定性、统一性、迁移与自行恢复要求，对现有代码逐项核对。参考 [Windows 应用开发最佳实践](https://learn.microsoft.com/en-us/windows/apps/get-started/best-practices)中的行为一致、安装管理、性能和辅助功能要求，以及[应用状态管理](https://learn.microsoft.com/en-us/windows/apps/develop/performance/state-management)中的增量保存、恢复及异常退出检查。

## 本轮已经落实

- 桌面、开始菜单和任务栏固定共用原生入口，定位正式程序与用户数据；重复打开先核对现有服务。
- Windows 目录迁移按系统位置、持久位置和目录身份定位；无明确线索的手动搬移提供一次选择。找不到已登记数据时停止并说明原因。
- 游戏身份、绑定和最近有效副本一起保存；外部更新协调到身体、语音与页面；旧窗口不能覆盖新版本，未保存行可合并重试。
- 完整退出提供明确入口：先保存草稿，录制期间阻止误退出；先松开按键再释放设备；收尾错误相互隔离，关闭结果需核对。

## 后续顺序与验收条件

| 优先级 | 已确认的缺口 | 用户影响 | 验收条件 |
| --- | --- | --- | --- |
| 最高 | `ControlKernel._save_general_settings` 捕获磁盘写入错误后不反馈；通用设置读取损坏内容时直接返回 | 设置可能只在当前运行生效，页面和下次启动的结果不一致 | 区分“已应用”“待保存”“保存失败”；普通动作识别持续运行；失败时保留草稿或待保存快照，有限重试；重启校验最近有效版本 |
| 最高 | 现有 `backup_user_data` 仅覆盖云端安装能修改的允许项，缺少完整的本地备份及恢复界面 | 手动复制容易漏掉动作、宏、校准或自建游戏 | 提供本地导出与恢复预览，显示游戏/动作数量；恢复前建立可回退副本；同机迁移保留身份，跨电脑恢复单独处理摄像头校准、配对和账户 |
| 较高 | 前后倾本机登记仍引用解释器、模型工程和权重的具体路径；源码桌面入口依赖已安装运行环境 | 配置目录已找到，但外部模型或运行环境被移动后功能仍可能不可用 | 将缺失资源具体列出，提供重新定位入口并核对文件；正式发布包自带匹配运行环境，升级后沿用数据；不依赖开发工具缓存目录 |
| 较高 | 桌面启动日志固定写入 `startup.stdout.log` 与 `startup.stderr.log`，新启动会替换上次内容 | 重启恢复后，上次失败的原因难以追查 | 按次数和总大小保留少量启动历史；提供诊断摘要导出；摘要显示版本、程序/数据位置和设备状态，排除配对钥匙、账户凭证、真人画面和录像 |
| 常规 | 资源开销分散在人体、头部、手部、前后倾、预览和页面刷新环节，已有状态数据尚未形成统一验收 | 优化单个模型后，整体占用仍可能不符合用户要求 | 分别测量空闲、只识别、开启游戏控制和录制时的完整开销；区分处理器、显卡、内存及端到端延迟；后台与隐藏页面停止不必要工作 |

最高优先的通用设置改造涉及运行中自动校准和学习写入，不能简单将所有写盘异常重新抛出；错误传播应区分实时处理与用户主动保存。现有游戏配置恢复不能据此宣称已经覆盖所有配置文件。

## 每项改动的共同要求

- 功能只保留一个权威状态和共享入口，新增动作继续使用统一绑定、校准与显示规则。
- 保存失败、操作取消、连接断开、设备缺失分别说明状态，给出能继续操作的入口。
- 改动使用隔离配置与合成输入检查，必要时再核对真实设备；构建、模拟检查与实机验收分别记录。
- 私人录像、训练数据、模型权重和本机性能记录不进入版本库。
- 视觉改动继续复用现有中性色、系统字体与设置行；本轮优先保证数据与操作结果可靠。
